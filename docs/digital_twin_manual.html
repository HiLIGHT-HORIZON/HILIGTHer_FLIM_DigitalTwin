HILIGHTer Digital Twin Manual, API Reference, and MCP Guide

This manual now documents the desktop workflow, the reusable backend/data/GUI APIs, the Model Context Protocol server, and the recommended prompt patterns for LLM-driven operation.

1. Architecture Overview

Physics Engine

Modulepython/backend/twin_engine.py

Forward model for excitation, decay PDFs, gating, Fisher precision, gridded MLE, Monte Carlo validation, and synthetic image generation.

Service Layer

Modulepython/backend/service_api.py

Shared orchestration surface used by the HTTP API, future software integrations, and the MCP server. This is the preferred programmatic entry point.

Desktop Automation

Modulepython/gui/automation_api.py

In-process API for controlling the live Qt workspace, reading plot state, and driving user workflows without scraping widgets manually.

MCP Server

Modulepython/mcp_server.py

Stdio JSON-RPC server implementing MCP tools, resources, and prompts so LLM systems can use the Digital Twin as an external reasoning and simulation backend.

2. Shared Service API

The core reusable API is DigitalTwinService. Another Python application can import it directly and use the Twin without the GUI:

from backend.service_api import DigitalTwinService

service = DigitalTwinService()
status = service.get_status()
service.update_config({"f_x_param": "tau1", "precision_validate_mc": True})
result = service.run_precision()

4. Data API Contract

The Digital Twin now exposes stable data-oriented artifacts for software integration:

  • Tau maps: fitted lifetime images for downstream visualization or QC.
  • Diagnostics snapshots: time vector, gates, IRF, and reference PDF for architecture introspection.
  • Pixel analyses: one-pixel decay, gate centers, analytic fit, and estimated lifetime.
  • Precision payloads: ideal reference, theory curve, and Monte Carlo statistics including compatibility tests.
  • GUI schema: software-readable description of workspace regions and actionable GUI elements.

5. GUI Automation API

Modulepython/gui/automation_api.py

When another Python application embeds or drives the live desktop, use window.desktop_api instead of touching individual Qt widgets directly.

from gui.main_window import HILIGHTMainWindow

window = HILIGHTMainWindow()
api = window.desktop_api
api.set_controller_state({"precision_validate_mc": True})
api.trigger_run()
precision_plot = api.get_precision_plot()

6. MCP Server

Modulepython/mcp_server.py

The server speaks stdio MCP with JSON-RPC framing (Content-Length headers), and it reuses the shared service layer. This allows an LLM runtime to treat the Digital Twin as a tool/resource provider.

7. LLM Integration Strategy

Recommended operating sequence for an LLM agent:

  1. Query get_status and get_config.
  2. Retrieve get_gui_schema to align assistant language with the desktop workflow.
  3. Run or propose configuration changes using update_config.
  4. Use run_precision for theory and MC validation.
  5. Treat Monte Carlo points with compatible == false as biased or statistically unsupported at the configured estimator-accuracy p-value threshold.
  6. Explain recommendations in terms of both theory and validation, never theory alone.

Core Context Injection

You are operating the HILIGHTer Digital Twin through its APIs or MCP server.
Always inspect backend status and current config before making recommendations.
Treat Monte Carlo compatibility at p >= the configured estimator-accuracy threshold as the validation gate for estimator trust.
Use the GUI schema to reference the correct controller tabs and widgets when guiding users.

8. Notes and Limits

  • The HTTP API and MCP server currently operate on the shared service layer, not the live Qt desktop instance.
  • The desktop automation API is in-process. It is intended for Python software embedding the GUI or controlling it in the same runtime.
  • The MCP server is functional over stdio and suitable for tool/resource/prompt integration with an LLM host.
  • For production multi-user orchestration, the shared service layer should eventually move from global in-memory state to explicit session-scoped instances.
