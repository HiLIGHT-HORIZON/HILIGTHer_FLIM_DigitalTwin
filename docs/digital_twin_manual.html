HILIGHTer Digital Twin Manual, API Reference, and MCP Guide

This manual documents the sanitized Python-first HILIGHTer Digital Twin workspace. It covers the repository layout, desktop workflows, APIs, MCP surface, launch/test commands, and export/persistence features used by the active application.

1. Product Scope

  • Numerical Fisher Information and CRLB estimation for virtual instruments.
  • Monte Carlo validation of Fisher-based predictions.
  • Bootstrap-based estimator-accuracy tests and confidence intervals.
  • Configuration of excitation, detection, gating, overlap, and acquisition parameters.
  • Synthetic image generation, fitting, diagnostics, and data products.
  • Software interoperability through Python APIs, HTTP APIs, desktop automation, and MCP.
  • Publication-oriented HTML report export with SVG and CSV assets.
Experimental import may still exist in compatibility paths, but it is not the main scope of this Python Digital Twin.

2B. Desktop Startup

Launch the desktop workspace from the repository root with:

python\run_desktop.bat

This launcher checks desktop dependencies, updates them when needed, shows startup status in the terminal and splash screen, and then opens the Qt workspace.

Desktop workflows are centered around:

  • RUN for precision, Monte Carlo, diagnostics, and report generation.
  • TEST for validation-image generation plus image fitting.
  • FIT IMAGE for re-running only the image fitting stage.
  • File > Save Workspace, Load Workspace, and Clear Workspace for state persistence.
  • View > Simulation Workspace and Image Validation Workspace for focused dock layouts.

3. Precision Math

Relative precision metric

F=σθ|θ|N

Photon efficiency

η=min(1,1F2)

Photon efficiency is physically capped at 1.0 in backend outputs and plots.

Scalar Fisher form used for the active precision parameter

I(θ)=N∑jgates(dPjdθ)2Pj

Sequential gating throughput penalty

Pj,seq=1GPj,hist

where G is the number of sequential gate acquisitions under a fixed total photon budget.

Bootstrap outputs

Estimator-accuracy p-values are evaluated with a bootstrap null on mean bias. Confidence intervals for F and F^-2 are produced by bootstrapping the Monte Carlo repeats.

Detection-gate optimisation objective

J=1K∑kKF(θk)

The currently implemented detection-gate optimisation algorithms minimise the mean numerical F value over the swept design grid.

Fisher Throughput metric used by excitation optimisation

T=ηpeak⁢S

where ηpeak is the peak photon efficiency over the active sweep and S is the throughput scale.

S={1fixed doseAexcAreffixed peak

For excitation-only throughput optimisation, the reference efficiency is the same instrument evaluated with Dirac excitation. For joint detection-plus-excitation optimisation, the excitation stage compares against the first detection-optimised Dirac-excitation design.

Throughput objective under sequential gating

T=ηpeak⁢S⁢1G

If the acquisition is sequential rather than histogram-bin, the throughput metric is reduced by the number of sequential gate acquisitions G.

The ideal reference is always computed as an ideal histogram-bin ceiling with Dirac excitation, no sequential penalty, no overlap penalty, no dead time, and no background carry-over from the live configuration.

Fisher Compression Mathematics

Fisher Compression starts from a fine contiguous histogram with probabilities p_i and score vectors u_i = ∇θ log p_i. For a compressed gate made of a segment S, the retained Fisher term is obtained from the aggregated probability and aggregated score numerator over that segment. In the scalar case used previously, the segment score maximized by the dynamic-programming solver is proportional to:

score(S) = ( Σ_{i in S} d_i )^2 / ( Σ_{i in S} p_i )

where d_i = ∂p_i / ∂ψ for the parameter of interest ψ.

When Use nuisance-aware effective FI (Schur complement) is enabled, the parameter vector is split into θ = (ψ, η), where ψ is the active X-axis parameter and η are the currently unfixed nuisance parameters from the decay-model controller. For each design point, the full per-photon Fisher matrix is partitioned as:

I(θ) = [ I_ψψ   I_ψη ]
            [ I_ηψ   I_ηη ]

and the effective information used by the compression rule is the Schur complement:

I_eff(ψ | η) = I_ψψ - I_ψη I_ηη-1 I_ηψ

In implementation terms, the fine-bin derivative for the parameter of interest is projected against the nuisance block to form an efficient scalar derivative before segment scores are accumulated. This keeps the dynamic-programming solver tractable while making the compression rule robust to nuisance-parameter coupling.

The nuisance-aware mode uses the currently unfixed decay-model parameters, excluding the active X-axis parameter itself, as nuisance parameters. If no nuisance parameters are active, the Fisher Compression rule reduces automatically to the scalar case.
The Fisher Compression implementation includes fixed-K optimisation and thresholded auto-compression. The relative loss test is referenced to the initial finer optimised partition after its own optimisation, not to the raw equal-gate starting point.

GaussianBounded width search over Gaussian excitation FWHM.Width minimum, width maximum, and dose/peak constraint.

The current free-form optimiser uses non-negative control points over the present excitation support width and optimises the waveform shape rather than introducing a second width search. The final waveform is stored in the configuration as the active free-form excitation profile.

Objective Modes

ObjectiveMeaningCurrent Behaviour
Fisher InformationMinimise the mean F value over the active design grid.Used directly by detection and excitation optimisers.
Fisher ThroughputPrefer faster or simpler acquisition while constraining photon-efficiency loss.Detection favours lower-complexity solutions when the selected algorithm can change gate count. Excitation now defaults to this mode and reports the best resulting excitation profile.

In practice, the throughput workflow keeps only candidates whose peak photon efficiency F^-2 remains within Max F^-2 Loss (%) of the applicable reference design, then chooses the candidate with the highest throughput metric. The percentage is interpreted as an absolute efficiency loss in percentage points. For example, a setting of 5% permits the peak efficiency to drop by at most 0.05. For excitation-only optimisation, the reference is the same instrument evaluated with an ideal Dirac excitation. For joint detection-plus-excitation optimisation, the excitation stage uses the first detection-optimised Dirac-excitation design as its reference. In Fixed dose (area), no extra photon-budget gain is assumed from pulse area, so throughput changes come only from the information efficiency delivered by the excitation and detection shapes. In Fixed peak, photon count is assumed to increase proportionally to the area under the excitation profile, so the throughput metric also scales by the relative excitation area. For detection, the throughput objective is most informative for strategies that can reduce gate count, especially Fisher Compression with auto-compress enabled. The optimiser reports the final excitation profile explicitly so the selected throughput trade-off can be reviewed after the run.

Auto-Compression Behaviour

If Auto-compress until max F loss is disabled, the starting partition for optimisation is the one already defined in the main controller. If it is enabled, the optimisation starts from an equal-width partition with Initial gates gates over the optimisation window, respecting the configured start and end anchors. The Instrument Diagnostics baseline in optimisation mode now shows that actual starting partition.

The solver then evaluates progressively smaller gate counts down to Minimum gates. It accepts each compression step while the peak photon-efficiency loss remains below Max F^-2 loss (%), measured in absolute percentage points against the initial finer optimised partition. The optimisation results explicitly report the final gate count reached.

Joint Alternating Optimisation

When both optimisation targets are enabled, the workflow alternates sequentially between the two enabled stages. Detection First and Excitation First define the order of each round, and Max iterations sets the maximum number of alternating rounds. The retained optimisation states shown in Precision, Accuracy, and Instrument Diagnostics are sampled from the combined cross-stage history.

When excitation optimisation is active, the final optimisation report also includes a summary of the best excitation profile, including profile family, active constraint, equivalent width, and either the final width or the free-form control-point solution.

12. Prompt Injection Strategy

  1. Call get_status and get_config.
  2. Read hilight://gui-schema or call get_gui_schema.
  3. Patch configuration only after establishing the baseline state.
  4. Use run_precision for theory and MC precision work.
  5. Use run_optimisation for detection-only, excitation-only, or joint optimisation workflows after confirming the selected strategy, objective, and execution order.
  6. Treat the diagnostics PDF ensemble as the family of PDFs generated by sweeping the active X-axis parameter.
  7. Treat the ideal reference as a histogram-bin ceiling even if the active configuration uses sequential gating.
  8. When compatibility flags exist, treat theory-only gains without MC support as tentative.
  9. Treat nuisance-aware Fisher Compression as an available option and expect the optimisation metric to change whenever unfixed nuisance parameters are present in the decay model.

15. Current Limits

  • The MCP server operates on the shared backend service layer, not a live Qt GUI instance.
  • Desktop widget and button execution remain available through the in-process desktop automation API.
  • Experimental import endpoints remain compatibility paths and are not the product center of gravity.
  • Sequential gating, explicit overlap, duplicate events, and independent duplicates remain under active development and should be treated as provisional engineering features rather than final validated modes.
