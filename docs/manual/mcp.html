MCP

Model Context Protocol server

The MCP server exposes the Digital Twin to LLM clients in a tool- and resource-oriented form. It is built on top of the same DigitalTwinService layer used by the HTTP API and desktop.

How to run it

Plain English

Start the MCP server as a local process and point your LLM client to it. The server speaks JSON-RPC over standard input/output.

For specialists

The server is python/mcp_server.py. It advertises tools, resources, and prompts and uses DigitalTwinService behind the scenes. The repository also includes python/tools/mcp_smoke_test.py.

python python/mcp_server.py
python python/tools/mcp_smoke_test.py

Using it with LLM hosts

Plain English

An MCP-capable client needs one thing from this project: a local command that launches the server. In this repository that command is python python/mcp_server.py.

For specialists

Most hosts ask for a server name, a command, and a working directory. The exact configuration schema varies by client version, so the examples below should be treated as patterns rather than guaranteed drop-in snippets.

HostWhat to configurePractical note
Codex / CLI MCP hostsRegister a stdio server whose command is python python/mcp_server.py and whose working directory is the repo root.Use the smoke test first to confirm that the environment can import the backend before connecting the host.
Claude Desktop / Claude MCP clientsAdd a local stdio MCP server entry pointing at python python/mcp_server.py.Keep the repo root as the working directory so relative imports and profile paths resolve correctly.
Gemini / Antigravity IDE style MCP clientsDefine a local tool server with the same stdio command and repo-root working directory.Use the prompts exposed by this server to steer the model into the correct workflow before it starts calling tools.
{
  "name": "hilighter-digital-twin-mcp",
  "command": "python",
  "args": ["python/mcp_server.py"],
  "cwd": "C:/path/to/DigitalTwin_Matlab"
}

Tools

The current server exposes status, config, precision, optimisation, simulation, diagnostics, phasor, session, schema, and profile-ingestion tools.

ToolPurpose
get_statusRead backend readiness and summary.
get_config / update_configRead or patch current configuration.
run_precisionRun theory and optional MC precision analysis.
run_optimisationRun integrated detection/excitation optimisation.
simulate_basic / simulate_advancedCreate and fit synthetic datasets.
get_data_summary, get_results_snapshot, get_tau_map, get_phasor_map, get_pixel_analysis, get_diagnostics_snapshot, get_theoretical_locusRead analysis products.
save_session / load_sessionPersist and restore session state.
ingest_instrument_profile_sourceCreate, save, and apply profiles from PDFs or webpages.

Recommended usage pattern: read status and config first, then decide whether to update config, run a workflow, or inspect outputs. This avoids an LLM issuing expensive or destructive changes before it understands the current instrument.

Resources

Resources are read-only named views over backend state.

ResourceMeaning
hilight://statusBackend readiness and configuration summary.
hilight://configCurrent full configuration.
hilight://gui-schemaMachine-readable desktop workspace schema.
hilight://data-summaryMap availability, shapes, and warnings.
hilight://resultsCurrent result snapshot.
hilight://tau-mapLifetime map only.
hilight://theory-locusPhasor theory loci.
hilight://diagnosticsTime vector, gates, laser profile, and reference PDF.

Prompt pack

The server exposes reusable prompt templates such as precision-audit, instrument-design, data-inspection, workspace-navigation, and optimisation-loop.

PromptWhen to use it
precision-auditWhen the model should review theory, Monte Carlo, and confidence intervals carefully.
instrument-designWhen the model should propose better excitation, detection, or gate designs.
data-inspectionWhen the model should interpret current maps, diagnostics, and pixel products.
workspace-navigationWhen the model should guide a user through the desktop workspace by concrete control names.
optimisation-loopWhen the model should analyse an optimisation run rather than just launch one.

Examples of MCP use

1. get_status
2. get_config
3. run_precision { "config_patch": { "precision_validate_mc": true } }
4. get_diagnostics_snapshot
5. run_optimisation { "config_patch": { "optimize_detection_gates": true } }
Use case: instrument-design review
- prompts/get instrument-design
- resources/read hilight://config
- resources/read hilight://diagnostics
- tools/call run_precision
- tools/call run_optimisation
Use case: validation-image inspection
- tools/call simulate_advanced
- tools/call get_results_snapshot
- tools/call get_phasor_map
- tools/call get_pixel_analysis { "y": 10, "x": 12 }

Instrument profile ingestion from PDFs or webpages

Call ingest_instrument_profile_source first on a source document to obtain extracted text and a suggested patch. Then refine the patch and call it again with save_profile=true and apply_profile=true to persist and activate the result.

tools/call ingest_instrument_profile_source {
  "source": "C:/specs/tcspc-camera.pdf",
  "profile_name": "TCSPC (vendor spec)",
  "save_profile": true,
  "apply_profile": true
}
