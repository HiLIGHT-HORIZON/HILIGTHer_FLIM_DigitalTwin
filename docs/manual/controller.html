Controller

The Digital Twin Controller

The controller is the single most important widget in the desktop workspace. It defines the decay model, laser profile, detector and gate geometry, image-validation settings, optimisation settings, and batch sweep settings. Almost every backend workflow starts by reading these values into PhysicsConfig.

Decay Model tab

Plain English

This tab defines what fluorescence decay is being simulated and how Fisher Information is evaluated. It also tells you which simulation core is active. If you only learn one tab first, learn this one.

For specialists

This tab controls decay_model, n_components, b_decay_wrapping, the effective simulation-core preference, the active X parameter for Fisher sweeps, the numerical sweep grid, and the Fisher / Monte Carlo execution settings.

ElementWhat it doesWhy it matters
Simulation core badgeShows whether the effective backend is ideal_poisson or event_driven.Green means legacy ideal Poisson, magenta means event-driven, amber means detector event effects are being approximated by the Poisson core.
DecayChooses the mathematical decay family from the built-in or saved custom models. The final entry is Add custom model....Changes the latent fluorescence model, available parameters, default sweep ranges, and gridded-MLE interpretation.
N componentsSets how many exponential components are active.Controls whether tau2 and alpha are meaningful.
Decay wrappingWraps long decays over the repetition period.Required when earlier pulses contribute to the current measurement window.
Show model equationsExpands a compact explanation of the current decay equation, laser contribution, and detector transfer model.Lets operators inspect the exact mathematical form without leaving the controller.
Decay parametersDefines the parameter values and which one becomes the active X-axis target for Fisher sweeps.The selected X-axis parameter becomes the variable swept in precision analysis and optimisation.
Background (%)Defines background as a percentage of the total decay mass.This keeps background sweeps meaningful across different time samplings and gate counts.
Precision Sweep ConfigurationControls X-axis min, max, steps, sweep spacing, and the MLE fine factor. Defaults come from the active model metadata.Defines the design grid used by both Fisher curves and many optimisation workflows.
Gridded MLE DefinitionShows the derived lookup range and lookup resolution.Helps users understand the actual numerical MLE grid implied by the sweep choices.
Fisher InformationControls Monte Carlo validation, confidence intervals, photon budget, repeats, p-value threshold, bootstrap count, and F-value photon basis.This pane defines how theoretical and MC precision outputs are computed and interpreted.

Excitation tab

Plain English

This tab describes the laser pulse shape. It used to be called the IRF profile in many places, but it is now presented more clearly as the laser profile because it drives the excitation envelope used by the decay PDF.

For specialists

These controls feed dt_excitation() in python/backend/twin_engine.py. Gaussian, rectangular, free-form, and ideal-dirac pulse families are all handled there, including optional burst modulation and detector-jitter broadening.

ElementWhat it doesWhy it matters
Period (ns)Sets the repetition period / acquisition window.Used by decay wrapping, phasor frequency, event-driven detection, and gate end anchoring.
Laser profileSelects Gaussian, Rectangular, Free Form, or Ideal (Dirac).Changes the excitation kernel used by the PDF and diagnostics.
FWHM / DurationDefines Gaussian width or rectangular duration.Controls temporal broadening of the excitation envelope.
PositionSets centre or start time depending on profile.Moves the laser pulse in time relative to the decay window and gate start.
Free-form editorVisual piecewise waveform editor for user-defined excitation shapes.Lets the user describe non-standard pulses and import optimiser-generated free-form solutions.
Burst ExcitationAdds a sub-pulse train inside the main envelope.Lets one laser profile act as the burst envelope.

Detection tab

Plain English

This tab describes what the detector actually measures: timing blur, deadtime, dwell time, gate shape, gate placement, gate overlap, and whether the Fisher metric should count missed photons or ignore them.

For specialists

The detector pane drives timing_jitter, detector_deadtime, event_pixel_dwell_time_s, b_multihit_mode, and event_multihit_capacity. The gating pane drives gate distillation, overlap handling, statistical exclusivity, and the shared F-value photon-basis semantics.

ElementWhat it doesWhy it matters
JitterSets detector timing jitter in ps.Broadens effective timing response and affects gate overlap and PDF alignment.
DeadtimeSets detector deadtime in ns.Can trigger detector event effects and the event-driven core.
Pixel dwellDefines how long one pixel is observed.Turns photons-per-pixel into count rate, which determines deadtime severity.
Avg count rateDerived from photon count and dwell time.Helps users immediately see whether they are asking for a physically aggressive acquisition regime.
Multihit Detection + Max events/periodControls how many events can be accepted in one repetition period.Sets first-hit or finite-capacity detector behaviour.
Afterpulsing (%)Sets the probability that an accepted detector event spawns one delayed afterpulse.Adds detector-originated follow-on counts in both simulation cores.
Dark count rate (cps)Sets the dark background count rate per second.Injects a detector-driven background and disables the manual decay-model background control.
Gate TypeEqual auto-generates edges; Custom uses explicit edge lists.Defines whether the instrument is user-designed directly or derived from constraints.
Gate Start Alignment / Gate End AlignmentConstrain the first and last gate edges.Important for optimisation and for reproducible instrument definitions.
Gate CollectionHistogram bin or Sequential.Sequential still exists as an under-development mode and changes throughput semantics.
Gate Overlap / Overlap EffectSets geometric overlap and the statistical interpretation of overlapping gates.Changes how photons are shared, clipped, or duplicated across overlapping gates.
Wrap aroundWrap gate tails around the period.Separate from decay wrapping; this affects gates, not the decay PDF.
Compute F-value onChoose All in acquisition period, All, or Only collected (disregard losses).Defines whether missed photons penalise the Fisher metric.

Fisher Information pane

Plain English

This pane tells the Digital Twin how to calculate precision curves. It defines the photon budget, Monte Carlo validation settings, confidence intervals, and how missed photons should influence the reported F value.

For specialists

The pane maps onto precision_photons, precision_validate_mc, precision_mc_repeats, precision_eval_ci, precision_ci_level, precision_bootstrap_resamples, precision_accuracy_pvalue, and the shared photon-basis semantics passed into TwinEngine.compute_fisher_info().

ElementWhat it doesWhy it matters
PhotonsSets the shared photon budget used in theory, Monte Carlo, and MC image validation.This is the main scale factor for attainable precision and for the detector average count-rate estimate.
Validate with Monte CarloRuns repeat simulations against the theory sweep.Helps identify where theory stays trustworthy and where the estimator becomes biased or unstable.
Evaluate CI + CI LevelComputes bootstrap confidence intervals for Monte Carlo summaries.Lets users judge uncertainty in the validation layer rather than only reading point estimates.
Bootstrap resamplesSets bootstrap sample count.Higher values stabilise CIs at the cost of time.
Estimator accuracy p-valueThreshold used when labelling MC compatibility.Controls how strictly estimator bias is called out in the UI and exports.
Compute F-value onChooses how missed photons should affect the Fisher metric.Changes the interpretation of F and F^-2, especially for delayed or lossy gate designs.

Batch Sweep tab

Plain English

Batch Sweep runs the same Fisher workflow several times while sweeping an instrument parameter, so you can compare whole families of precision curves.

Sweep familyPurpose
Laser pulse widthCompare excitation broadening.
Detector jitterCompare timing blur.
Detector deadtimeCompare deadtime distortion at fixed count rate.
Max events/periodCompare finite multihit capacity.
Gate rise/fallCompare smooth gate edges.
Number of gatesCompare gate-count architectures.
Burst rise/fallCompare burst-edge shapes.

Custom model editor

Plain English

The custom model editor lets you define new decay models, name their parameters, assign units, and set the default min/max/step values used for Fisher sweeps. Built-in models can be inspected there as templates and their sweep defaults can also be tuned.

For specialists

The editor persists user-defined models in python/profiles/decay_models/custom_models.json. Each definition stores a model key, display name, NumPy-compatible expression, parameter metadata, units, and sweep defaults. The backend evaluates the selected decay expression first, then applies the common background, laser, and detector-transfer layers.
