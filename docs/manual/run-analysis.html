Workflow

Run Analysis

Run Analysis is the main one-dimensional instrument-analysis workflow. It reads the current controller state, builds the decay model, distils the gates, computes Fisher Information across the chosen X-axis sweep, and optionally validates the result with Monte Carlo.

Fisher Information path

Plain English

This path asks: for a given instrument and a given photon budget, how well can the chosen decay parameter be estimated across the sweep?

For specialists

The desktop calls DigitalTwinService.run_precision(), which patches a temporary PhysicsConfig, builds x_range, then asks TwinEngine.compute_ideal_reference() and TwinEngine.compute_fisher_info() for the ideal and instrument-specific curves.

Monte Carlo validation

Plain English

Monte Carlo validation checks whether the estimator really behaves as predicted by theory.

For specialists

When enabled, the service uses TwinEngine.monte_carlo_precision_curve() and optionally attaches bootstrap confidence intervals. The accuracy p-value threshold is then used to flag estimator compatibility in the UI and exported reports.

F-value photon basis

Plain English

The same timing design can look better or worse depending on whether you judge it only by the photons it actually measured or by all photons that were present during the acquisition period.

For specialists

The three supported interpretations are documented in Maths. The option is propagated to the Fisher engine so that gated-out photons can be ignored, penalised within the acquisition window, or penalised against the full period.
